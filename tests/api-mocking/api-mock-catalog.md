# E2E API mock catalog

One row per mocked endpoint in `DEFAULT_MOCKS` (`mock-responses/defaults/index.ts`) and the shared mocks it spreads in, plus the feature mocks that overlay the typed APIs. `yarn test:e2e:sync-api-mocks` reads the `Sync config` table below, and the weekly workflow `.github/workflows/sync-e2e-api-mocks.yml` runs it.

**Consumer type** is the exported type the wallet or controller uses to read the response, declared in `api-response-types.ts`. Mocks marked `typed` end in `satisfies <type>`, so `yarn lint:tsc` fails when they drift. `none` means no exported type covers the endpoint.

**Sync mode** is what the sync does with the row. Only rows in `Sync config` are synced; every other row is `skip` in practice, and its reason says why:

| Mode          | What the sync will do                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------ |
| `write`       | Fetch the live API and rewrite only the shape (add/remove fields, keep existing values so asserted numbers stay).  |
| `report-only` | Fetch the live API and print drift, never write. Used when the mock is large, third-party, or the URL needs input. |
| `skip`        | Never fetched. The reason is the row's note.                                                                       |

## Sync config

This table drives `yarn test:e2e:sync-api-mocks` (`tests/scripts/sync-api-mocks.ts`). Rows not listed here are not synced (see the tables below for why).

- **ID**: stable name used in the report and `--only <id>`.
- **Mode**: `write` or `report-only`. `skip` rows are ignored.
- **Sync URL**: the live API request whose response shape the mock must match.
- **Mock**: `file#Export`. A `write` mock must be its own `export const NAME = <value> satisfies <Type>;` in `mock-responses/synced/`, which the script rewrites. A `report-only` mock may also be `file#Export@<sample url>`, which picks the entry of a mock list that matches the URL.
- **Options**: `map=<path>` marks an object whose keys are data (asset ids, currency codes), so keys are never added or removed. `/` is the root.

What `write` does: adds fields the API now returns (with the live value), removes fields it no longer returns, replaces a field whose type changed, and keeps every existing value. A live `null` keeps the mock value. Lists of primitives and empty lists are kept. Drift in `report-only` rows is printed and never written. After a write, `yarn lint:tsc` fails if the mock no longer satisfies its consumer type, which is the signal to update `api-response-types.ts`.

## Spec-level mocks (`defineApiMock`)

Mocks a spec or feature helper registers through `testSpecificMock` are built from the same definitions as the defaults. `api-mocks.ts` defines each catalogued endpoint once with `defineApiMock` (`define-api-mock.ts`): an id, the URL matcher, `urlFor(params)` for one chain or asset, and a default body whose generic type is the consumer type. A spec then writes only what differs:

```ts
testSpecificMock: combineMocks(
  priceSpotPricesV3.mock(() => ({ [assetId]: spotPrice(assetId, 1926.42) })),
  accountsSupportedNetworksV2.mock({ partialSupport: [] }),
  bridgeGetTokens.mock(() => GET_TOKENS_BASE_RESPONSE, { chainId: 8453 }),
),
```

Inside a custom `testSpecificMock` use `endpoint.register(server, overrides, params, { priority })`.

- **Overrides** are a partial that is deep-merged over a copy of the default (arrays replace), or a function `(body) => body` that returns the whole body. Both are checked against the consumer type, so a spec mock fails `yarn lint:tsc` when the type changes. Use the function form to replace a keyed map such as spot prices.
- **Priority** defaults to 999, the same as `setupMockRequest`, so a spec mock beats the `/proxy` passthrough that serves `DEFAULT_MOCKS`. Pass `{ priority }` where a spec needs to beat another spec mock.
- **`.always()`** is set on every rule. Without it mockttp answers the first request from the spec rule and the next ones from any other unused rule that matches (for example the global accounts supported-networks mock). `define-api-mock.test.ts` checks this against a real mockttp server.
- **Guard**: `api-mocks-guard.test.ts` fails when a file under `smoke-appium/`, `helpers/` or `api-mocking/` mocks a defined endpoint inline. Files that still do are listed there with the reason; migrate one and remove its entry (the test fails if a listed file no longer mocks inline).
- **New endpoint**: add an entry to `api-mocks.ts` and `API_MOCKS`, and a pattern in the guard. The default body should be the one `DEFAULT_MOCKS` serves, exported from its file, so the two cannot diverge.

## Live drift found while typing

Fixed in the mocks:

- `accounts.api` `/v4/multiaccount/balances`: the mock nested a `{ count, balances, unprocessedNetworks }` object inside `balances`. The live API and `V4BalancesResponse` are flat. The earn mock also lacked `count`.
- `accounts.api` `/v6/multiaccount/balances`: the mock sent `count` and no `unprocessedIncludeAssetIds`. The live API sends the reverse.
- `price.api` `/v3/spot-prices`: the mock sent `usd` and `eth` on every asset. The live API does not, and the controllers read `price`.
- `gas.api` `suggestedGasFees`: `baseFeeTrend` was `'stable'`. The live API sends `up`, `down` or `level`.
- `bridge.api` `/getTxStatus` default: `{ status: 'complete' }` fails the controller's validation (status enum is uppercase and `srcChain` is required). It is now a valid `PENDING` response, so an unmocked status request still leaves the transaction pending.
- `on-ramp-cache.api` `/v2/regions/countries` mock: countries used `emoji` and `currencies`, but `RampsService` reads `flag`, and the live API sends no `currencies`.

Not fixed (the type and the live API disagree, so the mock follows the type):

- Ramps `/v2/regions/countries`: live `states[].supported` is a boolean. `@metamask/ramps-controller` types it as `{ buy, sell }`. The mock follows the controller. The fix belongs in the controller.
- Price `/v3/spot-prices`: live also returns `liquidity`, `pricePercentChange5m` and `pricePercentChange4h`, which `CoinGeckoSpotPrice` does not declare. The type adds them. Live also returns `bondingCurveProgressPercent`, `totalSupply`, `holderCount` and `isMutable`, which are `null` for the sampled assets, so the sync does not add them.
- `accounts.api` `/v1/accounts/:address/transactions`: the mock (a live capture) fails `V1AccountTransactionsResponse` on `decimal`, `tokenId`, `accountId` and `null` fields. Left untyped.
- `accounts.api` `/v2/accounts/:address/balances` returned 404 on the last check. The mock is still registered and typed.
- `bridge.api` `/getTokens` returns fields `BridgeAssetSchema` does not validate (`coingeckoId`, `aggregators`, `occurrences`, `metadata`, `coinLabel`). The type adds the first four; `coinLabel` is not in any mock.
- `gas.api` `suggestedGasFees` returns `version`, which `fetchGasEstimates` drops. The type adds it.
- `price.api` `/v1/chains/:id/historical-prices` returns `marketCaps` and `totalVolumes`, which `V1HistoricalPricesResponse` does not declare. The type adds them.
- `ContentfulBannersResponse`, the Ramps countries default and the token list defaults are `[]`, so only their object shape is checked, not their items.
