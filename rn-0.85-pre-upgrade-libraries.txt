3. CODE CHANGES REQUIRED BY RN 0.85 (land pre-upgrade)
================================================================
(0.85 blog breaking-changes list cross-checked against our repo 2026-07-13)

CODE CHANGES WE MUST MAKE (grep-confirmed hits):
- StyleSheet.absoluteFillObject REMOVED -> replace with absoluteFill
    VERIFIED: 29 source files, ~38 occurrences today (spike's "28" has drifted +1).
    SAFE 1:1 codemod — in RN source absoluteFill and absoluteFillObject are the
    SAME frozen object (StyleSheetExports.js: `absoluteFillObject: absoluteFill`),
    so both spread sites `{...X}` and direct `style={X}` sites swap verbatim with
    zero behavior change. Plain find/replace of the exact string is sufficient,
    no AST codemod needed. Wave 1, lands on 0.83.
- C++ alias ContextContainer::Shared REMOVED (0.85 "Other Breaking Changes")
    NEW — was NOT in the original spike. We DO use it (blog claimed "not in use"):
    android/app/src/main/jni/MainComponentsRegistry.cpp:37 ->
      change `ContextContainer::Shared const &` to
      `std::shared_ptr<ContextContainer const> const &`.
    RN 0.85 app template already does this -> Upgrade Helper diff shows it.
    Left in place (NOT removed, still valid): EventDispatcher::Weak,
    ComponentDescriptorRegistry::Shared, ComponentDescriptorProviderRegistry.
- Jest preset 'react-native' REMOVED -> '@react-native/jest-preset'
    HIT: jest.config.js:34 `preset: 'react-native'`. Add new devDep. Upgrade PR.
- metro-react-native-babel-preset/-transformer REMOVED -> @react-native/metro-babel-transformer
    HIT: metro.transform.js:10 `require('metro-react-native-babel-transformer')`. Upgrade PR.

VERIFIED NO-OP FOR US (grep-confirmed clean, keep for audit trail):
- Node >= 20.19.4 — engines pins node ^24.16.0 (package.json:743). OK, no change.
- AccessibilityInfo.setAccessibilityFocus deprecated -> sendAccessibilityEvent —
    0 usages in our JS. No change (audit complete).
- Android legacy-arch removals (CatalystInstanceImpl removed, UIManagerHelper /
    ReactZIndexedViewGroup deprecated, NativeViewHierarchyManager stubbed,
    ReactTextUpdate now internal) — 0 references in our code. Risk is only in old
    native libs (already flagged: background-timer, os, i18n, default-preference, cookies).
- iOS RCTHostRuntimeDelegate -> RCTHostDelegate — 0 references. No change.
- Removed C++ aliases ShadowNode::Shared/Weak/Unshared/ListOf*, SharedImageManager —
    0 references. No change.

BEHAVIORAL CHANGE — TEST ONLY (no code edit):
- Pressable no longer unmounts event listeners in a hidden Activity — we use
    Pressable widely; regression-test Android hide/re-show flows (react-native-screens
    Activity, background/foreground) since a hidden pressable can still receive events.

RN 0.84 CHANGES WE ALSO ABSORB (we jump 0.83 -> 0.85 through 0.84):
- Hermes V1 becomes DEFAULT in RN 0.84 (not an SDK 56 thing) — opt-out exists
  (hermesV1Enabled=false / RCT_HERMES_V1_ENABLED=0) but plan to validate on V1
- iOS legacy architecture REMOVED from builds (RCT_REMOVE_LEGACY_ARCH default) —
  any lib still referencing legacy iOS APIs fails to compile
- Precompiled iOS core (.xcframework) is default (RCT_USE_PREBUILT_RNCORE=0 to
  disable) — can break libs with unusual header imports
- Android legacy classes DELETED: LazyReactPackage, CxxModuleWrapper,
  BridgeDevSupportManager, LayoutAnimationController, OnBatchCompleteListener, etc.
  — old unmaintained Android libs are the main risk (background-timer, os, i18n,
  default-preference, cookies — all already flagged for replacement above)
- RCTImage observer API changed — explicitly affects react-native-svg (hence 15.15.5)
- XHRInterceptor / WebSocketInterceptor DEPRECATED (-> CDP Network domain) —
  check our network debugging / nitro-websockets dev tooling for usage
- react-native-screens 4.25+ DROPS legacy-arch support and RN < 0.82

  setup. Must opt out (EXPO_PUBLIC_USE_RN_FETCH=1) or explicitly reconcile which
  fetch wins at boot. Verify before upgrade day.
- Toolchain floors: Xcode 26.4+, iOS minimum 16.4 (was 15.1), TypeScript 6.0.3,
  Node >= 20.19.4. Check CI runner images.
- Hermes v1 becomes the default JS engine — validate app boot + perf.
- expo-file-system: copy()/move() are now async (copySync()/moveSync() for old
  behavior) — the fs->expo-file-system migration (PR 4) should target the new API.
- @expo/ui DateTimePicker is a drop-in for @react-native-community/datetimepicker
  in SDK 56 (alternative to bumping to 9.1.0).
