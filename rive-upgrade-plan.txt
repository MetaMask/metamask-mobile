VERIFIED FACTS (registry / GitHub)
================================================================
1. Nitro package = @rive-app/react-native (repo rive-nitro-react-native,
   "Rive React Native v2"). Latest 0.4.19 (2026-07-17); 0.5.0-beta.1 on
   next. ~7 months old, ~40 releases, very active. Still 0.x with a
   deprecation ladder: v0.5 warns on sync APIs, v0.6 REMOVES them —
   port to the new data-binding hooks directly, not the shims.
2. Peer dep CONFIRMED: react-native-nitro-modules ">=0.35.10 <0.36"
   (floor raised in 0.4.12, thread-safety release). README's "0.33.2+"
   is stale. NOTE THE <0.36 CEILING.
3. Requirements: RN >=0.78 New Arch, iOS >=15.1, Android SDK >=24,
   Xcode >=16.4 — all fine on our 0.83 today and on 0.85/0.86 later.
4. COEXISTENCE NOT SUPPORTED (official migration guide): both packages
   bind the same RiveRuntime pod / app.rive:rive-android artifact.
   Migration must be ONE atomic cut-over PR covering all 20 files.
5. KEY FINDING — legacy 9.8.5 ships the IDENTICAL native runtimes as
   nitro 0.4.19 (iOS RiveRuntime 6.21.1 + Android rive-android 11.7.2;
   9.8.0 shipped 6.13.0/11.1.0). The 9.8.x changelog is native-runtime
   bumps only — no wrapper API changes. So if the viewport bug lives in
   the bundled runtime (per Rive support), 9.8.5 should fix MUSD-1200
   WITHOUT any API migration. Alexey's hunch is credible.
6. nitro-modules 0.35.5 -> 0.35.11 (recommended over 0.35.10): pure
   bug-fix line (codegen nested arrays, Kotlin dispose reset, Swift
   Promise races, ByteBuffer cursor, ThreadPool mutex). No API changes.
7. Peer matrix for nitro-modules 0.35.10/0.35.11 — ALL GREEN:
     nitro-fetch 1.3.3 (^0.35.2) OK | nitro-fetch 1.5.1 (^0.35.2) OK |
     nitro-text-decoder 0.2.x (^0.35.2) OK | nitro-websockets (*) OK |
     quick-crypto 0.7.15 (pre-Nitro, no dep) N/A
   Consistency bonus: rive-nitro's <0.36 ceiling matches our existing
   "nitro-modules stays 0.35.x" decision (nitro-fetch 1.5.1 ceiling).
