[x] SocialLeaderboardOnboarding — NUX — ISSUE FOUND + FIXED 2026-07-30 (iOS sim)
    RE-TESTED OK 2026-07-30 17:16 after fix: all 3 Follow-step avatars render
    distinct placeholder icons (blue/purple/green). Fix committed b1569a6d64
    "chore: fix leaderboard rive assets". Minor pending: eyeball Notify-step
    token logos (nova/blast/punch — same mapping, same fix, expected OK).
    Tested via dev-options reset → Homepage Traders entry. WORKS: 3 steps render +
    advance, no black warmup frame, live text bindings (0x… names + PnL) on Follow
    cards, overlay copy in sync.
    BROKEN: referencedAssets images NOT rendering — Follow-step avatars show as
    empty GREY CIRCLES; expected bundled placeholder is a BLUE rounded square
    (app/images/leaderboard_card_1_avatar.png, verified visually). Traders have no
    profile images (raw addresses) so placeholders should have shown.
    ROOT CAUSE (proven): Nitro binds referenced assets ONLY at file-load time
    (createCustomLoader returns nil when no mapping → empty native cache →
    late updateReferencedAssets is a silent no-op). useRiveFile ran at mount
    (+191ms per Metro log) before the frozen mapping settled, and the hook
    snapshots the mapping in a ref on first render — so passing it later can
    never work. Legacy bound assets at native VIEW mount, which the existing
    referencedAssets mount gate covered (confirmed on origin/main).
    FIX APPLIED 2026-07-30 (SocialLeaderboardOnboarding.tsx): extracted
    useRiveFile into render-null child OnboardingRiveFileLoader mounted only
    once referencedAssets is non-null → file load's first render has the
    mapping; parent gets file via onFile={setRiveFile}. Render gate/dispose
    lifecycle unchanged. Re-tested OK (see [x] header above); pushed 8ccaeb91c8
    after rebase onto remote branch (remote had been rebased onto newer main;
    4 migration commits patch-identical, dropped cleanly).
