# Money Earnings Allocation View-Test Design

## Goal

Fix the failing `MoneyEarningsView` component-view test and add screen-level
coverage for the Allocation tab using real rendered state and mocked HTTP
responses.

## Scope

- Update `MoneyEarningsView.view.test.tsx`.
- Extend the Money Earnings component-view API mock helper with deterministic
  composition and historical APY responses.
- Do not change production components.
- Do not replace existing focused `AllocationTab` unit tests.

## Behavior

The disabled-tab test will request the disabled `apy` tab, verify the screen
defaults to Earnings, press APY, and verify Earnings remains active. Allocation
is enabled and therefore is not part of that assertion.

A separate component-view test will render the screen with Allocation selected,
wait for the composition response, and verify the Allocation panel plus
representative chart, market-table, and allocation-details output.

## Test Data and Mocking

The existing historical earnings mock remains the default. The shared Money
Earnings mock helper will additionally intercept:

- Local composition requests generated by `useMoneyVaultComposition`.
- Historical APY requests generated by `AllocationDetails`.

Each endpoint will have a valid default response and explicit cleanup. Tests
will continue to use the existing renderer, preset, test IDs, and localized
strings. No component or hook mocks will be added to the view test.

## Verification

Run the focused component-view Jest file with `jest.config.view.js`, lint the
touched test files, and run the component-view formatting/self-review checks.
