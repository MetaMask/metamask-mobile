Money Account full footprint migration

A resumable, idempotent migration function that moves vault position, mUSD, approvals, 7702, CHOMP, and Card bindings from an old Money address to a new key. No UI. On-chain exit is one EIP-7702 delegator atomic batch.

Frozen

isFrozen(source) is true in INVENTORIED through RE_PROVISIONED. Money deposit/withdraw builders throw. IDLE and VERIFIED_INERT are not frozen so residual sweeps can run.

Point of no return

BATCH_EXECUTED and later: abort is refused. Resume only. Funds already sit on destination as vmUSD/mUSD.

Option B — one atomic batch

TransactionController.addTransactionBatch from the old Money address, atomic: true, disableSequential: true, requireApproval: false. Inner calls all succeed or the whole tx reverts. Gate 1 failure stays IDLE — no A-W fallback.

No teller withdraw/deposit. No add-signer inner call — Stateless DeleGator has none. Native last. Rebuild amounts immediately before submit; destination never changes.

Gate 1 — batch-from-self

  • isAtomicBatchSupported({ address: source, chainIds })
  • eth_getCode starts with 0xef0100
  • Impl is EIP7702StatelessDeleGatorImpl
  • Fail → blocker atomic-batch-unsupported

Gate 2 — keep 7702

  • Do not type-4 reset to 0x0
  • After batch: root Delegation old → new
  • New key sweeps residuals via redeemDelegations anytime
  • No N-day watch, no watchUntil
  • Unknown impl → hard blocker, not sequential txs

Resume contract

Crash, kill, offline, or lock must never submit a second exit batch or change destination. Chain is source of truth; persisted status may only jump forward.

Constraints

  • No UI — function is called after consent. planHash and destination are still pinned.
  • Destination exists — MoneyAccountController.createMoneyAccount(newEntropyId) already ran. One Money address per entropy (m/44'/4392018'/0'/0).
  • Vault as ERC-20 — transfer vmUSD shares. Do not call teller withdraw/deposit.
  • Perps/Predict — protocol accounts stay on the user EOA. Only block in-flight Money↔service MM Pay txs. After re-provision, funding pointer is activeMoneyAccountId.
  • No N-day watch — new Money address already operates old via residual Delegation. sweepFormerAccount anytime. No watchUntil, no payroll window.
  • Resumable — persist exitBatchId at submit; migrate for the same pair calls resume(); never double-submit.
  • Do not disassociate the old CHOMP address — durable old→new history needs it.

01 Types, plan hash, controller skeleton

02 Inventory + blockers

Inject MigrationRpc. Do not touch Engine in unit tests.

03 Gates

gates.ts

assertAtomicBatchSupported and assertStatelessDelegator. Failures are blockers, not fallbacks.

04 CHOMP revoke-intents adapter

chompRevoke.ts

Vendored POST /v1/intent/revoke until @metamask/chomp-api-service ships revokeIntents. Already-revoked is success.

05 Teardown + restore

teardown.ts · restore.ts

Intents → storage delegations → Card unlink amount: '0'. Restore from TORN_DOWN via upgradeAccount(source) + re-link cap.

06 Encode batch calls

encodeCalls.ts

vmUSD transfer, mUSD transfer, approve(0)s, native last. Skip zeros.

07 Execute Option B batch

executeBatch.ts

One addTransactionBatch. Revert stays TORN_DOWN. Destination locked. Recollect balances first.

08 Residual Delegation

residualDelegation.ts

Root Delegation, empty caveats, after batch confirms. Copy the signed blob onto formerMoneyAccounts[old] so a later migrate does not wipe the sweep key. No N-day expiry.

09 Re-provision + verify + primary pointer

reprovision.ts · verify.ts · moneyAccountController selector

upgradeAccount(destination) (existing idempotent sequence) + Card re-link + activeMoneyAccountId.

10 Freeze Money tx builders

freeze.ts · moneyAccountTransactions.ts

assertMoneyAccountNotFrozen at the start of deposit/withdraw batch builders.

11 State machine + Engine wiring

MoneyAccountMigrationController · messenger · Engine.ts

migrate / resume / abort. Auto-resume on unlock. Card link injected as a constructor hook.

12 On-demand former-account sweep

sweepFormer.ts · MoneyAccountMigrationController

sweepFormerAccount(old) anytime after completion. New key redeems the persisted residual Delegation to the pinned dest. No watchUntil, no poll.

  • Backend migration-lock endpoint (local freeze is the mobile lock)
  • Extracting a core @metamask/money-account-migration-controller package

  • Hybrid/MultiSig on-chain add-signer ABI

External dependencies

  1. CHOMP POST /v1/intent/revoke — confirm path/body; swap to package method when published.
  2. User-storage metadata type for residual Delegation must not be ingested as a CHOMP auto-intent.
  3. Optional Accounts API old→new alias for cross-client history. Local formerMoneyAccounts is enough for this client.

How to invoke

After the destination Money account exists:

await Engine.context.MoneyAccountMigrationController.migrate({
  source: oldMoneyAddress,
  destination: newMoneyAddress,
});

Anytime after completion, leftovers on a former address (no watch timer):

await Engine.context.MoneyAccountMigrationController.sweepFormerAccount(
  oldMoneyAddress,
);

On app launch / unlock, init calls resume() if status is in-flight. migrate for the same source and destination also resumes. Destination of a former sweep is the pinned formerMoneyAccounts[old].newAddress.
