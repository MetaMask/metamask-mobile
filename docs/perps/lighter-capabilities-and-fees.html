How MetaMask can earn with low user fees

Lighter supports fee capture natively. MetaMask has not wired it into this integration yet. Lighter calls it Partner Attribution: the user approves MetaMask, each order identifies MetaMask's Lighter account and fee, and Lighter credits MetaMask in USDC when perpetual trades generate integrator fees. Our current provider instead quotes metamaskFeeRate: 0 and supports Standard accounts only. [L1, L2] [C1]

The PM explanation

  1. Get permission. The user approves MetaMask as an integrator, with a maximum fee and optional expiry. Different L1 owners normally require L1 approval and L2 confirmation. Approval can be revoked.
  2. Tag the order. The signed order carries integrator_account_index, integrator_maker_fee and integrator_taker_fee. This is Lighter's equivalent of a builder code. The protocol does not infer MetaMask from the wallet brand or API key.
  3. Collect on trades. The protocol credits perpetual integrator fees in USDC to the specified integrator account. This is an additional user-paid fee, not an automatic share of Lighter's existing fee. Treasury withdrawal and reconciliation still need implementation and proof.

The published perpetual integrator ceiling is 10 bps, with 0.01 bp increments. That is a limit, not a recommended price. Confirm live limits with systemConfig before approving or charging fees. One basis point is 0.01%. The SDK's integer fee value divided by 1,000,000 is the fee fraction: 100 = 1 bp, 1000 = 10 bps. [L1, L2, L5]

Low-fee option to evaluate: Plus + a small MetaMask fee

Lighter lists Plus maker and taker fees at 0.5 bp / 0.005%. A hypothetical 1 bp / 0.01% MetaMask integrator fee would make the combined trading charge 1.5 bps / 0.015% per filled notional. This is a pricing proposal for discussion, not an approved MetaMask rate or a tested quote. [L3]

Illustration: $1,000 filled notional, Plus fee 0.5 bp, hypothetical MetaMask fee 1 bp
Recipient Rate One $1,000 fill
Lighter 0.005% $0.05
MetaMask 0.01% $0.10
Total trading fee 0.015% $0.15

An opening fill and a closing fill of $1,000 each would total $0.30 under those assumptions. Fees apply to traded notional, not posted margin. Spreads, slippage, funding, liquidation and transfer/withdrawal costs are separate. “Low fee” must not be presented as “free,” and a small notional rate can still be material at high leverage.

Maker and taker integrator fees are configured independently, allowing a different maker price to be evaluated. Do not default to the maximum fee merely because the protocol permits it.

Native integrator fee The trader pays the approved additional fee. Predictable configurable collection, subject to protocol eligibility. Not zero-fee trading.
Referral share Lighter distributes 10–30% of eligible gross fees from referred users, depending on the referrer's tier. No extra MetaMask surcharge, but the user still pays eligible venue fees. Negotiated subsidy / revenue share Would require Lighter or another agreed budget to pay. No MetaMask-specific agreement verified. A MetaMask-funded rebate reduces its own net revenue; it does not create free protocol income.

Referral payouts are documented as weekly L2 transfers with a $1 minimum. Trades carrying nonzero integrator fees are excluded from referral kickbacks and rebates: do not count both revenues on the same trade. The commercial program says referral attribution is fixed at signup and cannot be added later; API wording elsewhere disagrees. Confirm onboarding eligibility before promising revenue from existing MetaMask users. [L4, L6]

Important eligibility change and documentation conflicts

The official Partner Attribution notice says that from September 14, 2026, Standard-account partner trades and new integrator approvals are rejected. Plan nonzero integrator fees around Plus or Premium, with explicit user consent to the tier's venue fees. Our Standard-only integration cannot simply add an order tag and start collecting. [L1]

  • The API guide still says “Both standard and premium accounts are accepted” in Definitions, but its Requirements mandate Plus/Premium for nonzero fees. The newer notice is broader. Treat Standard zero-fee attribution as unresolved, not supported revenue capture.
  • The API guide allows L2-only approval for zero fees, whereas the overview describes signature requirements by L1 ownership without that exception. Confirm the zero-fee case; it does not establish nonzero revenue.
  • Referral API descriptions suggest attribution can change later, conflicting with the commercial program's signup-only rule. The program also labels July 28, 2026 a Monday, although that date is a Tuesday. Confirm the exact eligibility cutoff and rule with Lighter before using it in forecasts.
  • These are verified documentation claims as of September 15, not live fee-credit tests. No account tier, approval or order was changed for this research.

What must be built and proven

  1. Select a business model and user-facing price. Confirm applicable Lighter Core network/tier rules and commercial eligibility; do not assume Robinhood Chain has identical terms.
  2. Support eligible non-Standard account fees safely in Core, replacing the current refusal only after fee units, quotes and history are covered by tests. Add explicit tier selection/consent rather than silently upgrading users.
  3. For native fees: configure MetaMask's receiving account per network, add integrator approval/revocation/expiry and signed order fields through the WASM bridge, and show venue + MetaMask + total fees before submission. Verify the pinned signer supports these operations; generic signing support is insufficient proof.
  4. Reconcile partial/full fills against both the user's charges and the integrator's credited USDC, then verify treasury withdrawal. Cover cancellation, failed orders and approval limits. Mainnet financial testing requires separate authorization.

Hyperliquid comparison: its existing integration already sends an approved builder: { b, f } payload. The configured standard maximum is 10 bps, with discounts/subscription exceptions; native TWAP has no builder field. Lighter has a comparable protocol mechanism, but uses an account index, its own fee units and different eligibility rules. This document does not compare all-in prices for every market or certify Hyperliquid settlement. [C2, C3]
