consider RETARGETING the final upgrade PR to 0.86.2 + SDK 57 directly
(0.83 -> 0.86 in one PR). Every pre-upgrade library PR in the 0.85
ladder applies unchanged; we'd skip one full app-release soak cycle on
0.85. Trade-off: larger single validation surface, and 0.85 has one
month more community soak than 0.86. Decide before the final upgrade PR.

2. CODE CHANGES REQUIRED
================================================================
NONE. Grep-verified 2026-07-29 against our repo:

BEHAVIORAL CHANGES — TEST, DON'T EDIT:
- Android 15+ edge-to-edge overhaul (headline feature): fixes to
  measureInWindow, KeyboardAvoidingView, Dimensions, StatusBar+Modal,
  nav-bar contrast. Regression-pass all keyboard/modal/bottom-sheet
  flows on an Android 15/16 device — measurements may legitimately
  change out from under workarounds.
- WebSocket Cookie header NO LONGER STRIPPED — directly relevant to our
  Nitro WS dev routing (wss:// -> Nitro, ws:// -> RN built-in): the RN
  built-in path now forwards cookies. Audit WS auth assumptions.
- Views with scaleX/scaleY: 0 no longer receive touches.
- ExceptionsManager.reportErrorsAsExceptions only disabled by explicit
  `false`; PerformanceObserver durationThreshold defaults to 104ms —
  check Sentry/perf tooling config.
- Blob content provider fixed on New Arch (may CURE blob quirks).

3. BLOCKERS & RISKS
================================================================
[!] Detox — SAME #1 BLOCKER AS 0.85, UNCHANGED. wix/Detox#4963 still
    open (last activity 2026-07-14, ours). Official support README caps
    at RN 0.84; no release supports 0.85 OR 0.86 Android New Arch E2E;
    zero 0.86 issues filed yet. Whatever mitigation we pick for 0.85
    (disableSynchronization/reflection patch/Appium window) carries to
    0.86 as-is. 0.86 adds no NEW E2E risk, but doesn't fix the old one.
[!]
 (OPEN): Android/RN 0.86/Fabric crash in
    SurfaceMountingManager with React Navigation stack animations —
    hits our exact stack. Track before upgrade day; test nav
    transitions heavily on Android.
[!] Expo SDK 57 known issue: reanimated + Hermes V1 memory regression,
    +25-30% RSS just from importing reanimated. Workaround: worklets
    bundle mode. Budget a perf pass.
[!] expo#47539: bare-project build failure on Xcode 26.3 (Swift
    data-race). Pin CI + local to Xcode 26.4 exactly.
[!] `expo prebuild` in SDK 57 now CLEANS android/ios by default
    (--no-clean to opt out) — guard against anyone clobbering our
    native dirs.
[~] blob-util #479 (OPEN, updated 2026-07-21): NativeEventEmitter crash
    on bridgeless cold start — retest on 0.86.
[~] screens #4151: Android Fabric SIGSEGV reports mention 0.86.
[~] Braze 19.1.0: unconstrained peer, likely runs, but Braze has only
    validated 21.0.0 vs RN 0.85.3; nothing published for 0.86. The
    deferred 21/22 bump remains post-upgrade validation hygiene.
[~] @metamask/react-native-webview fork 14.6.0: no 0.86-specific
    breakage found, but upstream moved to 15.0.0/16.0.0 (16 drops Paper
    entirely). Build fork vs 0.86; fork rebase decision unchanged from
    0.85 spike.
[~] keyboard-controller #1470 (worklets warnings) still open — same
    status as 0.85, no fix in 1.22.x.

ADJACENT DEADLINE (not 0.86-specific, but lands in the same window):
[!] Firebase drops CocoaPods distribution Oct 2026 (registry read-only
